## Deployment objective and decision sequence

The objective is one offline assistant that improves useful answers over the pinned Qwen3.5-0.8B-Base, preserves its existing capabilities, and can retrieve changed evidence from at least 131,072 actual input tokens. An architectural claim also requires a matched one-pass model. We measure user-visible accuracy, action grounding, latency to the first token, whole-request time and peak allocation together. Aggregate wins alone cannot qualify a family with a regression.

### One recurrent backbone for ordinary questions and live actions

The two-backbone release qualified its tools while incurring a loading cost when users switch between tools and plain questions. A new conversion removes the instruction model’s original layer 21 and applies its physical gated-delta layer 20 at both depths, with independent native states. It learns to match the removed layer’s actual hidden vectors on raw prose and ordinary tool conversations. Both modes share these weights and the same resident decoder arrays. The explicit tool catalog activates the previously qualified tool factors at the final layer. This tests an architectural alternative to carrying a separate tool backbone. It draws on Bae et al.’s use of depth-specific adaptation to compensate for weight tying. [Published method](https://proceedings.iclr.cc/paper_files/paper/2025/hash/54d6a55225cebbdc16fbb0e45c5bdf2b-Abstract-Conference.html)

The registered pair includes 40 previously unenrolled human questions and 52 historical public calls or field requests. Each user-visible result is scored against untouched ordinary Base. A family loss, a lost historical success, a missing latency or peak gain, or an inadequate hidden-state match closes this fit. Passing permits a matched one-application control, followed by fresh independent mixed requests and long-context qualification if warranted. The ordinary-prefix arithmetic trial asks whether a recurrent action decoder can recover the operations in a real word problem after reading the model's own first 96 reasoning tokens. ReAct motivates evaluating a thought, action, observation and final answer together. Here the model must generate the program itself and can revise a wrong draft. The frozen pair uses 48 previously unenrolled ASDiv and SVAMP questions. Both arms have exactly the same schema, IDs and 384 tokens per turn. The primary decision includes final quantities, verified callbacks, per-source retention, time and memory. A positive result opens a matched one-pass finisher comparison. ### Asking for a missing file, row or column

The qualified two-pass tool decoder is the reference for preference training on 384 external When2Call questions. Each model response is paired with a rejected alternative. A distinct 48-question validation split measures changes in the relative sequence likelihood. The evaluation uses a new read-only CSV provider. For each of 16 lookups into two project reports and the two Palmer Penguins tables, the model receives a complete request and a separate request missing one required value. The latter includes a user follow-up with the missing value. The model has to ask for the right input before calling, execute the right operation, and return the exact scalar. A further 22 public numerical requests measure retention.
