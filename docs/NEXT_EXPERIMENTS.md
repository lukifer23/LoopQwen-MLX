# Research decisions

## Deployment objective and decision sequence

The objective is one offline assistant that improves useful answers over the pinned Qwen3.5-0.8B-Base, preserves its existing capabilities, and can retrieve changed evidence from at least 131,072 actual input tokens. An architectural claim also requires a matched one-pass model. We measure user-visible accuracy, action grounding, latency to the first token, whole-request time and peak allocation together. Aggregate wins alone cannot qualify a family with a regression.

**Released assistant.** `exports/tool-language-packed-03` passed the independent full-history and product checks. Its parent field release scored 21/50 against 12/50 for Base on one cold-start request stream. It gained seven net file answers and three SQLite results, tied on human reading, and lost one net arithmetic answer. Fifteen mode switches accounted for 15.24 s of its 20.33 s to first tokens, compared with 4.26 s on those requests for Base. The original experiment missed its general-purpose promotion gate. ## Word problems

Use the 32-update K2 adapter when correct answers on grade-school word problems are needed within 256 generated tokens. It improved over untouched Base on three measured groups and used less generation time. With 1,024 tokens, Base solved eight more of the 48 fresh questions. The longer-budget gate failed on both sources. Base remains the general-language reference and the higher-accuracy choice on this longer-budget cohort. It tests whether a localized passage actually produces a correct generated answer. A selected passage alone earns no answer credit. ## Release decision and remaining comparisons

The central comparison is a single installable recurrent assistant against the untouched pinned Base. Each experiment freezes its decision and maximum native runtime in the registry. The following questions determine what can enter the release.

| Question | Direct evidence | Decision |
| --- | --- | --- |

Both must complete before replacement. |
| Does extra computation help choose arithmetic operands? | A native shared layer selects operators and arguments for the real calculator. Its learned action horizon is capped at six. Both arms answer the same 48 unseen human problems. | Require better final numeric answers and correct executions, with no loss on either source. ### Arithmetic reasoning before a live call

The ordinary-prefix arithmetic trial asks whether a recurrent action decoder can recover the operations in a real word problem after reading the model's own first 96 reasoning tokens. ReAct motivates evaluating a thought, action, observation and final answer together. Here the model must generate the program itself and can revise a wrong draft. The frozen pair uses 48 previously unenrolled ASDiv and SVAMP questions. Both arms have exactly the same schema, IDs and 384 tokens per turn. The primary decision includes final quantities, verified callbacks, per-source retention, time and memory. A positive result opens a matched one-pass finisher comparison.
