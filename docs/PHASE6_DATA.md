# Presentation order as a controlled variable

The Phase 6 namespace inherits the MIT-licensed 3,840 training and 384 development permutations from Phase 5. The builder verifies the parent manifest against the published copy and checks the actual split bytes. A new manifest binds the Phase 6 renderer, parent streams and experiment registration. Labels, map IDs, initial states and the seed-109 epoch permutation are fixed across arms. The sealed cohorts are excluded from model selection.

A SHA-256 fingerprint of the study seed, epoch, map ID, example ID and rendering policy seeds a local PRNG. The randomized renderer uniformly shuffles all eight source/destination pairs. The optional mixed policy uses a registered 25% canonical fraction. A tokenization cache uses the complete rendered prompt. The depth-independent recurrent and three-head inputs keep the same text at every requested hop.

Every final development evaluation pairs the same maps under canonical order, reversal, rotations by one and four, and eight seeded random orders. Training and evaluation use separate seeds and policy names. Reported mean random accuracy weights each map equally. The paired bootstrap draws 384 maps with replacement, retaining all their renderings and comparing arms on the same draw. Exact agreement, joint correctness and the fraction of maps correct under every tested order measure different properties.

The map generator intentionally excludes an early return to the starting state. A first-hop readout scored against a third-hop target is therefore a weak comparator. The primary control trains directly on each requested terminal task. [Renderer](../loopqwen/data/pointer6.py) · [Registration](../experiments/phase6.json)

## Generated and open data for the next review

The 3,840 distinct training maps supplied 3,840 first-hop, 2,496 second-hop and 1,152 third-hop labels. Each map appeared in a single order during the first epoch. On the fixed 96-map random-order subset, third-hop accuracy rose from 15 at update 120 to 79 at update 360 and 94 at update 480. A second epoch with fresh displays is a direct test of additional exposure. Generating fresh map IDs would change instance diversity as well. Version future generators, enforce map-level split exclusion across all renderings, verify every state with independent traversal and matrix propagation, and report exposures by hop.

For an external question benchmark, GSM8K provides human-written math problems, numeric final answers and published train/test splits. A small fixed development sample disjoint from every previously used training item would probe transfer to natural-language arithmetic. Pin the source revision, verify its license and file digests, audit overlap with the existing optional GSM8K ingestion, and reserve the official test for frozen comparisons. Public release also permits possible exposure during base-model pretraining. [GSM8K publisher](https://github.com/openai/grade-school-math) · [Publisher license](https://github.com/openai/grade-school-math/blob/master/LICENSE)

DeepMind's CLRS suite supplies algorithmic generators and intermediate supervision. A single relevant graph task could supply an external structural stress test after the pointer experiment. Review code and data terms separately, document the conversion from algorithmic inputs to prompts, and give the two models identical questions. No CLRS or new GSM8K examples entered this Phase 6 study. [CLRS benchmark and licensing](https://github.com/google-deepmind/clrs)
