# Phase 2 study protocol

Start from d1c6cd60. Preserve the original models, split files and reports. Record the original suite in an isolated output directory. Compare full-context and windowed cached decoding against matching uncached attention on the same token positions. Audit padding, shift, restoration and native derivatives.

Generate 24,000 verified training problems, balanced development and sealed ID/OOD splits. Run a short answer-only and trace pair. Screen curriculum, interpolation, placements and adapter capacity using development examples only. Choose the recurrent candidate by development answer NLL on the common answer-only protocol, report exact answers and retention separately. Keep sequencing, precision, initialization and adapter policy matched within each pair. Use adjusted ranks or a common projection subset for placement screening when the hybrid layer mix differs.

Freeze the winning config and evaluation IDs before confirmatory scoring. Train seeds 43, 53 and 67 from the base. Compare with a dense data-matched twin and a dense control with extra updates calibrated to elapsed training work. Evaluate actual additional sampled candidates under a measured latency budget. Use seed and item pairing, show uncertainty and preserve individual predictions. Run the three-seed local screen before considering substantially longer training.

Profile real Metal forward/backward at 128–512 tokens, measure system memory and test adapter versus fused task outcomes. Commit milestones on main. Phase 2 results use their own namespace.

Stage A used 72 updates, batch four, and 288 problems per arm. Trace instruction-following on development differed sharply from answer-only prompting. Keep the declared answer-NLL selection rule, report trace accuracy separately and increase the final trace decoding sample to 45 per split, balanced across all 15 family/difficulty cells. All arms receive 90 answer-only generations, 150 teacher-forced examples per protocol and 48 prose paragraphs per final split. The ID/OOD cases and prose are shared across seeds. Trace decoding is bounded at 128 tokens. Before final scoring, validate native left-padded batched caches against single-item inference in BF16 and FP32.

Stage B–D screens use 24 updates and verified traces. Select a single policy and then train for 84 updates per matched arm. Retain a constant post-warmup rate with five warmup updates across all controls, including the time-budget control. Each dense time-budget run stops at the first full update reaching its seed-matched loop's measured update time. Model/data loading, validation and checkpoint serialization are outside this budget. Native timings are specific to the local Mac. Reproducing a time-matched run on another Mac can entail a different update count.

The Stage A development results motivated one additional 24-update screen with mixed answer and trace prompts, plus its matched dense twin. Include its loop in the same answer-NLL selection rule. This is a development-stage amendment before final-case scoring. The architecture-only screens still use identical trace supervision. All screen arms use 150 teacher-forced development examples per protocol, 60 answer-only generations and 15 trace generations.
