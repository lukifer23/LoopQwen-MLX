# Phase 4 data and scoring

Track A and the primary dual-exit pilot use the immutable V2 training file and the historical example-level mixed answer/trace protocol. A fixed seed determines order and batch boundaries. The position cap changes the shape seen by MLX within a logical update. The existing V3 development ID and OOD files contain 150 items each; the language-retention sample contains 120 independent passages. Phase 3's sealed files remain outside the evaluator.

The separate eight-state pointer task uses 3,840 training maps and 384 development maps. Each map is a permutation. The training and evaluation map identities are disjoint; initial states are chosen so that a return to the start within three hops cannot trivialize the terminal label. This restriction changes the conditional difficulty of the task. The input contains the complete map, starting node, requested hop count and a readout cue. A lookup iterator and independent one-hot vector propagation verify six labels. Only the loss and diagnostic scorer receive those labels. A verbal rendering uses the same underlying map. The public state distribution and task generator are project MIT code.

The optional V4 text mixture contains 7,500 training examples and 300 examples in each of validation and OOD. Three fifths come from the corresponding existing V2 split. One fifth uses new DAGs and one fifth uses pointer programs with verified textual state transitions. Graphs with two to four roots, randomly extended branches, joins and irrelevant sinks use randomized job names and display order. Paths to the target are checked by topological dynamic programming and exhaustive enumeration. Each solved dependency closure has a relabel-invariant fingerprint using distinct node durations; changing only an irrelevant sink cannot create a new example. V4 DAG durations are outside the V3 generator ranges. OOD graph regimes vary scale, introduce fan-out followed by reconvergence, or combine both changes. The manifest records actual tokenized-file SHA-256 hashes, source manifests and per-protocol counts. Its procedural license is MIT. The V4 training corpus has 30,841 answer-format or 590,344 trace-format supervised tokens if rendered entirely in the respective format. Trace length and state dependence are distinct properties.

Under weighted CE, direct responses receive final-answer weights and EOS receives its separate weight. For traces, tokenizer offsets partition final numeric tokens, numeric/operator-bearing intermediate tokens and remaining scaffold tokens. Language tokens use an explicit language weight. These are heuristics. Copying an answer already printed in a gold trace can give a tiny final-token NLL. Direct-answer NLL and generated answer correctness measure different behavior. Pointer certificates must assert each transition of the specified map in order. Unsupported derivations retain their separate verifier status. [Verifier](../loopqwen/evaluation/trace_verifier.py)

The completed primary gated training trajectory contained 3,283 direct-answer examples and 3,157 trace examples. The direct protocol contributed 13,808 supervised tokens, and traces contributed 236,403. Direct examples thus supplied 51.0% of examples and 5.5% of scored positions. The scheduled logical batches had 2.64% padding after physical splitting.

A predictor using only training-set frequencies conditioned on the start node and hop count got 53/384, 62/384 and 54/384 terminal labels correct at depths one through three. The no-return constraint makes uniform guessing among the seven non-start nodes 14.3% accurate in expectation.

The CPU data audit rechecked 3,240 new textual state/DAG certificates and 25,344 pointer-label transitions across all 4,224 disjoint permutations. It compared the historical sealed file digests with their original registration. Reproduce with `python scripts/phase4_data_audit.py`.
