# Actual dependency constraints and historical candidate releases

Every task uses a complete wheel pinned by a real application. The 20 training projects come from the Pydantic source lock. The ten held projects come from the frozen python-jsonschema/jsonschema lock and are distinct from the earlier held and training project names excluded by the enrollment. Each selected wheel declares an unconditional direct dependency with a nonempty version constraint and a unique version pinned by the application. The original wheel digest and embedded METADATA digest bind the tool response. [Pydantic lock](https://github.com/pydantic/pydantic/blob/6449f80db0214a95178b6b80a3613451b924a4f1/uv.lock) · [jsonschema lock](https://github.com/python-jsonschema/jsonschema/blob/4ba8468a0130d890328bb821786bb74bdca32298/uv.lock)

Each decision uses the actual pinned version or the nearest release in the ordered history that the requirement excludes. Every selected version had an actual distribution uploaded by 2026-11-14 and listed as unyanked at collection. The release inventories record versions, filenames, digests and upload timestamps from the public PyPI JSON interface. Each wheel is read without importing it. A correct pair must distinguish both published candidates using the wheel’s own requirement. This tests the declared dependency, with no claim about a complete solver or installation. [PyPI JSON API](https://docs.pypi.org/api/json/) · [Version specifiers](https://packaging.python.org/en/latest/specifications/version-specifiers/)

Use `.venv/bin/python -m scripts.wheel_archive_sources --acquire` followed by `.venv/bin/python -m scripts.dependency_sources --acquire`. After acquisition both sources can be verified offline. The exact preregistered model input contains the ordinary public wheel-metadata schema. The training and held partitions are chosen without consulting any model answer.
