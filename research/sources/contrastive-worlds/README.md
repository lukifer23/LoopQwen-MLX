# Learning whether an answer changes with the source

There are 11,642 complete candidate training turns and 318,778 positive target tokens. A human answer enters both sides of each of 3,979 pairs. It is the preferred answer under the source that supports it and the rejected answer under the other source. Both directions use the actual rendered prefix. Separate turns teach the original schema discovery, human SQL program or recorded service call. These data were assembled before opening the preceding conditional model’s direct comparison. They did not train that checkpoint.

| Source | Enrolled cases | How the evidence changes |
|---|---:|---|
| Human SQL | 942 questions | An original table and a separately annotated changed version have different human answers. We run the same human program in SQLite on both and also teach the answer after a complete unrestricted row read where both versions fit. |
| Qualitative reasoning | 1,201 human pairs | Two authored questions use the same background and the same two choices. The correct answer reverses. The order of choices is identical within each pair. |
| Grounded service follow-through | 900 pairs across 13 methods | Each published service transcript supplies its own original conversation, function declaration, arguments, complete recorded result and natural human reply. Two or more fields supporting each reply are absent as complete field values from every row of the other result. |

For future development evaluation, a hash fixed 24 complete original table files, 24 complete reasoning backgrounds, and 24 pairs of previously unused service dialogues (48 dialogues). All questions from a held source table or reasoning background were excluded from training. The held service replies and conversations were excluded. An independent audit found none of 117 full held questions or long service replies inside any original or new training content field. We cannot audit the upstream model pretraining. The service result rows come from the original simulator-backed dialogue release. They support teaching how to use a returned value. Runtime database evaluation executes real SQL.

Rebuild with `.venv/bin/python -m scripts.contrastive_world_material` and `.venv/bin/python -m scripts.verify_contrastive_material`. Both enforce source checksums and reproduce the stored data. Each paired row carries an original source key or a digest of its two service IDs. The retained table versions, source schemas, original answers, licenses and independent checks are available in the related source collections.
