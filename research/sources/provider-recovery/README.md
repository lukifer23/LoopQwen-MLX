# Repairing a failed read on a real database

On 178 tool-enabled requests in the completed conditional comparison, the trained loop issued 328 callbacks and encountered 49 provider errors. The loop called again on all 20 requests where it saw an error, often with the same arguments. None of its later callbacks succeeded. Base saw an error with another turn available on 41 requests and obtained a successful later callback on 19. Both systems returned zero grounded final answers on requests with any provider error. These conditional rates describe different self-selected sets of requests. On the eight common opportunities, the corresponding later-callback counts were zero and five. [All measured trajectories](../../../paper/conditional-primary-tool-recovery.csv) · [Family and provider breakdown](../../../paper/conditional-primary-tool-recovery.json)

This training-only collection uses the original questions, human SQL programs, natural-language answers and SQLite files from the published CoSQL dialogues. We select two individually executable human statements from different training databases. We submit the second statement to the first database through the actual read-only provider. The registered error condition is an SQLite missing-table or missing-column exception. We expose the same short exception class that the ordinary application returns. A corrective action must execute the original expert statement on the correct database and reproduce its stored cells. The mistaken pairing is a controlled intervention created by this project. The people in the original dialogues did not make these deliberately crossed calls. [Original paper](https://aclanthology.org/D19-1204/) · [Original project cohort](../database-dialogues/README.md)

Of 220 source cases, 211 fit whole and nine were excluded by the input/output length limits. They span 62 training databases and 102 distinct crossed programs. Each source contributes four complete supervised turns covering schema discovery after an error, query repair before or after the schema has been inspected, and the original human reply after a successful query. The corpus contains 844 turns, 758,031 opening tokens and 39,799 supervised output tokens. We kept all previously reserved CoSQL evaluation databases apart. These examples have yet to train a native candidate.

An independent replay read the serialized messages against clean copies of the source databases. It verified 844 actual errors, 844 schema returns and 633 successful query returns across the four overlapping views. It also verified each crossed query on its own original database and each final human reply. Run `python -m scripts.provider_recovery_material --verify` and `python -m scripts.provider_recovery_replay` with the pinned CoSQL archive available. ## Exact CSV keys and a second tool on the same table

The conditional loop had 27 CSV lookup errors and 22 database query errors. For the CSV cases we searched 942 previously enrolled training questions for a unique keyed lookup that reproduces the independently annotated answer on every source variant. In 123 questions, the caller’s literal spelling occurred in the original human question and differed from the stored key. For example, the original question uses “michigan state” and the table stores “Michigan State”. The standard exact-match CSV provider raises a real exception on the caller’s spelling. The correct answer must also change between the two enrolled table versions.

Each source contributes two repair paths. After an actual case-insensitive SQL discovery read exposes the key, the model can retry the original CSV operation with the exact observed spelling. When only the schema is known, the model can switch to the human-authored SQL program on the same data. Both paths include a successful real callback and a final answer. The 123 questions generated 984 complete training turns and 37,618 labels. A separate program reproduced the failures and both successful answers on all 723 available table versions, then replayed every callback in all 984 enrolled histories. These are constructed teaching trajectories on original user questions and data. They make no change to either current fit. ## Repairing a wrong search column

We rebuilt each original environment and reissued all 127 failed callbacks from both deployed models. Of 27 loop CSV errors, 21 used a different search column from the enrolled action, 18 used a different key, and 16 used a different return column. These counts overlap. Every failed call returned the class `ValueError` to the model. The underlying provider reported that no record matched the submitted key. Zero calls differed in key only by capitalization. The exact-spelling material above targets a separate failure mode. [Every failing action with its underlying diagnostic and expected fields](../../../paper/conditional-primary-provider-errors.csv)

The role-repair collection uses 162 original user questions whose correct search column, entity and return column identify the annotated scalar across every available variant. A controlled failed call keeps the correct entity and changes a column. The reply must select the appropriate fields using the user's actual question and the supplied column declarations. No earlier successful tool call or expert SQL appears before the repair target. We verified 99 sources with another search column, 34 with the output field used as the search field, and 29 with both fields swapped. A separate replay confirmed every failure and corrected scalar on 922 labeled table versions, then checked both source-changing worlds in all 648 training turns. There are 24,428 supervised output labels. These questions overlap the spelling collection, so their counts cannot be added to estimate unique sources. [Case inventory](csv-role-qualification.json) · [Independent replay](csv-role-independent-replay.json)

In the 19,233 earlier and contrastive fitting turns, 8,083 have a prior tool observation and zero include a structured provider error. The shared-query corpus also has zero such cases. The three repair collections contain 2,476 complete supervised turns on 373 distinct original user questions. Of those turns, 1,449 target an actual corrective action and 1,027 target the answer after a successful repair. This audit covers the project’s supplied training histories. It cannot measure errors discussed in ordinary text or exposure in the pretrained Qwen weights. [Source hashes and counts](exposure.json)

## A successful query can answer a different question

Across the 48 changed-table requests, the earlier conditional loop issued 58 SQL calls. Of the successful single-cell reads with a non-null value, 12 returned the human answer and 28 returned a different value. The latter occurred on 27 requests. The loop repeated the incorrect value as its final answer on 19 of those requests and recovered to a grounded correct answer on zero. Base issued eight query calls and had no comparable non-null single-cell observation. These counts complement the provider-exception analysis above. [SQL and actual returns](../../../paper/conditional-primary-changed-statements.csv) · [Final answers](../../../paper/conditional-primary-requests.csv)

We paired two original human questions and their independently verified expert SQL programs on each of 105 training tables. Each program succeeds on the real database and returns a plausible single cell. Only one answers the current question. On the original table the *identical* prior query, schema and return occur under both questions. One context calls for a direct answer and the other requires the model to write a different query. Both directions occur. The foreign answer must have the same numeric or nonnumeric type as the human answer and differ from it on every eligible version of that question. The historical questions, programs, observations and accepted answers come from the original source material. The crossed histories are teaching examples constructed by the project.

The collection contains 210 distinct human questions with 420 examples in each of three groups. They cover accepting an appropriate result, issuing a corrective query after a successful read, and delivering the answer after the correction. An independent replay checked the two statements on 1,280 question-table versions, then reproduced 1,260 schema calls and 2,100 SQL calls from the serialized supervised histories including target actions. It also confirmed 210 pairs with identical histories after the user message and opposite required behavior. This material has 35,608 target tokens and did not train either frozen candidate.
