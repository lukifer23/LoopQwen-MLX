# Offline single-checkpoint replay after the terminal fits

Use the untouched certified BF16 Base followed by the terminal BF16 loop. Each model directory has its own complete donor tensors, tokenizer, runtime wheel and, for the loop, its trained coefficients and recurrence configuration. Every asset is a regular file. Start a new offline interpreter outside the checkout with only the current model directory and installed wheel. Load the model once. Run the same ordered requests, record full traces and costs, wait for process exit, then advance to the other model. A copy-on-write file may share storage blocks with another independent file.

This is a runtime and grading audit on already-scored development sources. Take the first registered reasoning, chat, calculator and CSV sources, with all original and changed presentations and both real own-history follow-ups (10 responses per arm). Use 512 generated tokens per turn, greedy thinking-enabled Qwen decoding, three tool turns and the original public providers. Apply the locked rubric only where exact input tokens, output tokens, tool arguments, provider responses, visible answers, stopping status and attention histories match the original. Report each discrepancy. Require 20/20 matching traces, exclusive nonoverlapping model processes, and separate loaded-model, request and cold times. Stop on the first process, resource or trace integrity error. Allow 240 additional profile worker-seconds within the existing development budget. A replay validates reproducibility. Generalization and causal depth retain their registered separate tests.
